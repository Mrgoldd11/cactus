# Запись экрана: что возможно в этом окружении

Проверено (2026-11-07), ничего не устанавливалось:

| Что | Результат |
| --- | --- |
| Экран | один монитор 1920×1080 (RTX 3060 Ti) — запись в Full HD без масштабирования |
| `ffmpeg` / `ffprobe` | **нет** ни в PATH, ни где-либо найденный |
| OBS Studio | нет |
| Python `cv2` / `mss` / `imageio_ffmpeg` | нет (Python 3.12 есть) |
| `winget` | есть (v1.29) → можно поставить ffmpeg одной командой |
| Playwright | `@playwright/test` 1.64 в проекте; браузеры/`ffmpeg` Playwright **не скачаны** (нет `ms-playwright`) |
| `claude` (Claude Code CLI) | есть, 2.1.311 |
| Xbox Game Bar (Win+Alt+R) | есть в Windows 10, но его нельзя надёжно управлять из скрипта; запись — только руками |

## Рекомендуемый способ

1. **Поставить ffmpeg** (нужно ваше согласие: скачивание ≈ 100–150 МБ):

   ```bash
   winget install Gyan.FFmpeg
   ```

   Это единственная установка, без неё нормального видео не получить; монтаж (склейка, наложение
   голоса, титры, финальный экспорт для YouTube) тоже делается ffmpeg.
2. **Запись рабочего стола** ffmpeg: `ddagrab` (Desktop Duplication, ffmpeg ≥ 6) —
   качественнее и быстрее `gdigrab` для WebGL-панели «Мир»; аппаратное кодирование NVENC.

   ```bash
   ffmpeg -f lavfi -i ddagrab=framerate=60:draw_mouse=1,hwdownload,format=bgra -c:v h264_nvenc -preset p5 -cq 18 raw/03c-world-panels.mp4
   ```

   (запасной вариант: `-f gdigrab -framerate 60 -draw_mouse 1 -i desktop`, кодек `libx264 -crf 16`).
   Лучше записывать **весь рабочий стол** 1920×1080, окно приложения — на весь экран.
3. **Управление приложением** — скриптом Playwright (`_electron.launch`, как в
   `apps/desktop/e2e` и `scripts/beta-shots.ts`) с «медленными» действиями: паузы между шагами
   0,5–1,5 с, плавное движение мыши (`mouse.move(..., {steps: 30})`). Playwright двигает мышь
   внутри страницы, а не системным курсором, поэтому ffmpeg его не увидит. Решение — **внедрить
   в страницу свой курсор**: `<div>` стрелка, следующая за событиями `mousemove` (добавляется
   только в записывающем скрипте, в код приложения не входит). Альтернатива: системный
   курсор через PowerShell `SendInput` — сложнее, но реальнее.
4. **Видео средствами Playwright (`recordVideo`) не использовать**: нужен отдельный `playwright
   install ffmpeg`, это покадровый скринкаст VP8 ~ низкого качества, 25 fps, плохо ведёт себя с
   WebGL (рывки в «Мире»).
5. **Звук**: записи без звука. Ваши файлы озвучки накладываются на этапе монтажа:
   `ffmpeg -i video.mp4 -i voice.wav -c:v copy -c:a aac -shortest …`. Подгонка длительности:
   если озвучка длиннее видео — `tpad`/стоп-кадр или замедление; короче — подрезка пауз.

## Что получится, а что нет (честно)

- ✅ Записи приложения (всё из `shotlist.md`, кроме 05 и 05b): полностью автоматизируется.
- ✅ Видео 1920×1080, 30/60 fps, H.264, экспорт для YouTube (`-movflags +faststart`).
- ⚠️ Окно должно быть на весь экран, поверх ничего не должно появиться (уведомления Windows,
  антивирус). Лучше записывать с выключенными уведомлениями.
- ⚠️ Мышь и клавиши ведёт скрипт — это выглядит «роботизированно» (идеальные траектории).
  Смягчаем: паузы, плавные траектории, небольшой разброс. Если нужно «по-человечески» — вы
  можете повторить сценарий руками под мою подсказку.
- ⚠️ Игра Kenshi (`05b`, мост): запись DirectX-игры лучше делать в оконном режиме; управлять
  игрой я могу только через плагин Kenshi Bridge (камера, телепорт, пауза), по ROADMAP «Показать
  в игре» в игре не проверялась. Сегмент необязательный.
- ❌ Нет возможности «подделать» ИИ-запись: AI-сегмент снимается только с реального сеанса Claude.

## Запись ИИ-сегмента (05)

Нужен живой Claude. Два варианта, рекомендую первый:

1. **Claude Code (CLI) в терминале рядом с Cactus** — окно терминала в правой половине экрана,
   Cactus — в левой (или картинка в картинке при монтаже). MCP-сервер Cactus подключается к
   Claude Code по настройке из «Справка → Подключить ИИ (MCP)…»; запуск без меня-как-ИИ:
   `claude -p "<запрос из shotlist>" --mcp-config <конфиг>`, вывод виден в терминале. Плюсы:
   полностью воспроизводимо и скриптуется, можно сделать несколько дублей. Минусы: расходует
   ваш тариф/лимиты Claude (несколько коротких запросов) — нужно ваше «да».
2. **Claude Desktop** с подключённым MCP — вы запускаете запрос сами, а я записываю экран.
   Выглядит ближе к тому, как будут пользоваться люди, но не автоматизируется.

Правила: показываем реальный ответ Claude, без монтажных подделок; допускается ускорение
ожидания (таймлапс ×4) и вырезание пауз, это указываем в озвучке («ответ ускорен»). Токены/ключи
в кадр не попадают: вход в Claude уже выполнен, окно настроек аккаунта не показываем.

## Что потребуется от вас

- «да» на `winget install Gyan.FFmpeg`;
- «да» на несколько запросов Claude Code с вашего аккаунта (для записи 05);
- голосовые файлы по сегментам `01…08` (WAV/MP3), либо одним файлом с метками времени;
- по желанию — запуск Kenshi для необязательной записи 05b.
