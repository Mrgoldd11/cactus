# Мир Kenshi в файлах игры (разведка этапа 7b)

Всё ниже проверено на Kenshi Steam 1.0.65 (`D:\SteamLibrary\steamapps\common\Kenshi\data`)
скриптами по самим файлам; что не проверено — так и помечено. Код: `packages/core/src/world/terrain.ts`,
`packages/core/src/node/terrain.ts`, тест `packages/core/test/terrain.game.test.ts`.

## Какие папки используются

- `data/newland/` — текущий мир. `data/land/` и `data/leveldata/` — старый мир (карта 1024²,
  30 зон); игрой не используется, редактор их не читает.
- `data/newland/leveldata/` — базовый `leveldata.level` и одна зона; слои `Newwworld/` (334 файла),
  `Dialogue/`, `rebirth/` — накладываются по порядку, как записи `.mod` (это уже делает `WorldIndex`).

## Координаты

- Ось y — вверх (Ogre). x и z — по земле.
- Мир — квадрат **64×64 зоны по 4608 единиц**, центр в (0, 0): x и z от −147456 до 147456.
- Файл `zone.X.Y.zone`: `X = floor(x / 4608) + 32`, `Y = floor(z / 4608) + 32`. Проверено на
  всех 11714 экземплярах зданий ванили: расхождений 0. Зоны в файлах — от 2 до 62 по X, от 0 до 62 по Y.

## Рельеф

- Карта высот — `data/newland/land/fullmap.tif`: TIFF little-endian, **16385×16385, 16 бит без знака,
  без сжатия, одна полоса** с 43686-го байта (537 МБ). Рядом `fullmap.cif` (160 МБ) — вероятно, она же
  в сжатом виде игры; формат не разбирали, он не нужен.
- Пиксель (столбец, строка) = `((x + 147456) / 18, (z + 147456) / 18)`: 18 единиц на пиксель,
  строки идут по z, без отражения.
- Высота = значение × **9800 / 65535**. Подобрано по зданиям (перебор 9765…9830 даёт резкий пик
  у 9800) и подтверждено: `world Y pos` здания = рельеф + y экземпляра у 76 % зданий (см. ниже).
- Цвет земли — `data/newland/land/overlaymaps/colour.I.J.png`: 8×8 картинок RGBA по 2048²,
  каждая на 2048×2048 пикселей карты высот. `distant.png` (128²) — весь мир крупно.
  **I — столбец (по x), J — строка (по z)**: правый край `colour.3.3` совпадает с левым краем
  `colour.4.3` (разница 0), а нижний — с верхним краем `colour.3.4`. Альфа-канал — не прозрачность
  (в среднем ≈ 100 из 255, назначение не выяснено): цвет берём только из RGB.
- `navtiles/` (`tile*.hkt`, 3996 шт.) — сетки навигации Havok, `blendmap.png`/`blendinfo.dat` —
  смешивание текстур земли — не разбирали; `biomemap.png` — см. «Биомы».

## Биомы и растительность

- `data/newland/land/biomemap.png` — 1024², цвет пикселя = поле `index` записи BIOMES. Столбец — x,
  строка — z, как у карт цвета (проверено сравнением с `ground colour` биомов).
- BIOMES: текстуры земли `base`/`slope`/`cliff` со своим `tiling`, диапазон склона, обрыв,
  `fade distance`. Единица `tiling` не проверена — считаем «повторов на зону 4608».
- Растительность: BIOMES `foliage` → FOLIAGE_LAYER → `meshes` (v0 — плотность) → FOLIAGE_MESH
  (модель, `texture map`, `material type` 4 = вырез по альфе, `leaves mesh`, размер, сдвиг вниз,
  склон, высота над морем, кучки, обход городов). **Мест растений в файлах нет** — игра
  раскладывает их сама. Редактор раскладывает по тем же правилам, но случайно: места не те, что
  в игре. Не проверено: плотность (считаем «кучек на зону 4608²») и склон (100 × тангенс).
- Прозрачность (вырезы листвы, `material type` 4 и `leaves mesh`): шейдер игры
  (`data/materials/deferred/objects.hlsl`, `clip(normalTex.a - threshold)`) режет по **альфе карты
  нормалей**, а альфа диффузной текстуры — блеск (у `TreesAtlas01.dds` она почти вся 0). Для листвы
  маска — `leaves normal`, без неё редактор берёт `normal map` (у `ThinTree 01`, `Joshua Tree` в
  `leaves normal` пусто, а `normal map` — тот же атлас; в игре не проверено). Без карты нормалей
  игра берёт `flat.dds` (альфа 1) — вырезов нет.
- `material type` 2 = TERRAIN (158 записей; у 68 — `Boulder*`, `MonuRock*`, `BlackRock*`,
  `Barkworm_Pillar*` — своей текстуры нет): на модель ложится текстура земли биома (fcs.def:
  «Terrain mode uses textures from the current biome», `Feature_Terrain` в `mapfeature.material`).
  Редактор красит такие картой цвета земли по X/Z мира с рисунком скалы
  (`CinderRidge-Rockloop_DIF.dds` в трёх проекциях). У остальных 90 своя `texture map` — их
  редактор рисует ею (с цветом земли они выглядели плоскими). Текстуры `…_HI.dds`, которых нет в папке игры, редактор заменяет обычными
  (`…_DIF_HI.dds` → `…_DIF.dds`).

## Объекты в зонах

- В зоне: запись `INSTANCE_COLLECTION` `0-buildinglist` с экземплярами (`instances`) и записи
  состояний `GAMESTATE_BUILDING` (имя, фракция, отряды, «внутри здания», `world Y pos`…). Экземпляр
  ссылается на свои состояния строковыми id (`states`), id состояний повторяются в разных зонах —
  искать только в том же файле.
- Экземпляр: `target` — строковый id записи из `.mod` (обычно BUILDING), `position` (x, y, z):
  x, z — абсолютные координаты мира, **y — высота над землёй**, `rotation` — кватернион
  в порядке файла (w, x, y, z).
- Поле состояния `world Y pos` — высота здания в мире. Проверено на всех 11 737 зданиях ванили:
  у 8 926 (76 %) `world Y pos` = рельеф (`fullmap.tif`) + y с точностью до 5 единиц; остальные
  стоят выше земли (ярусы, платформы, крыши). Для отрисовки берём `world Y pos`.
- После слияния слоёв в `0-buildinglist` ≈ 32600 экземпляров, из них ≈ 20900 — пустые
  (`target` = '', позиция 0,0,0): так поздний слой убирает экземпляр. Живых зданий ≈ 11700.
- Экземпляры без состояния здания (≈ сотни) часто стоят не на земле — назначение не выяснено.
- **Здание без состояния игра считает стройплощадкой** «на продажу» (0/400 стройматериалов) —
  проверено в игре на поставленной модом «Древней лабе». У всех 14 637 состояний зданий ванили
  `is complete` = true, `version` 270, `<i>construction mats` = v0 i-й ссылки `construction` (без
  ссылок — `0construction mats` = `build materials`), `construction progress` — их сумма. Новое
  здание редактор ставит с таким состоянием (`newBuildingState`), без хэндлов сохранения
  (`handle*`, `residents*`). Что здание после этого готовое — в игре ещё не проверено.

## Города и прочее в `leveldata.level`

- Города: `GAMESTATE_TOWN_INSTANCE_LIST` `townlist` — 304 экземпляра на 169 записей TOWN, позиция
  — центр города, состояние `GAMESTATE_TOWN` со списком зон города.
- Дороги: записи `ROAD` с экземплярами-точками (≈ 21000), `roadfoliage` (2725), `roadlist` (2109,
  все в 0,0,0). Пока не рисуем.

## Интерьеры (`interiors.level`)

Проверено по файлам ванили (4 слоя, 410 раскладок) и разбором в `packages/core/src/world/interior.ts`.

- Раскладка — запись `INSTANCE_COLLECTION` с id `<здание>-<Имя>` (`727-gamedata.base-Noble House`).
  Поля: `associated building` (BUILDING), `is exterior` (снаружи: вывески, флаги; id `EXT-…`),
  `is shop`, `is bar`, `is recruitment`, `flophouse`.
- Экземпляры раскладки — мебель (BUILDING: стены, кровати, сундуки, верстаки) и точки предметов
  (`ITEM_PLACEMENT_GROUP`). Позиция и кватернион — **от начала координат модели здания**, не мира.
- Состояние экземпляра:
  - у мебели — `GAMESTATE_BUILDING` с id `<ключ>-S23` (имя, фракция владельца, `floornum`, замок,
    `player furniture Y offset`, точки использования);
  - у точки предметов — запись `ITEM_PLACEMENT_GROUP` со своим id (`base data sid` — что лежит,
    `floornum`).
- Мод пишет в свой `interiors.level` только изменённые экземпляры раскладки (запись раскладки — с её
  полями) и состояния полными копиями. Удаление объекта из нижнего слоя — экземпляр-«удаление»;
  свой новый объект просто стирается. Новые ключи и id состояний — `<n>-<мод>-INGAME`, n — от
  `lastId` файла мода.
- При сдвиге по высоте вместе с позицией сдвигается `player furniture Y offset` (и `world Y pos`,
  если есть) в состоянии.
- Какую раскладку берёт здание в мире — поля состояния здания `interior layout name` /
  `exterior layout name`. Где имени нет — игра выбирает сама. Пример: Outpost (Застава c-III) — 54
  в мире, 9 с именем раскладки, 19 без имени. Поэтому правка раскладки касается **всех** зданий
  этого типа с ней (а безымянных — как повезёт).
- Жильцов, охрану и товар в раскладках нет: их ставит игра по шаблонам здания и города.
- Файл большой, читается отдельно, только когда открыт интерьер (`WorldEdits.addFiles`). Новый
  объект без шаблона состояния (ставим впервые в этой раскладке) в игре **не проверен**.
